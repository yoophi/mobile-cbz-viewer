# 단일 페이지 열람 검증 (#6)

서재의 준비된 책에서 `/reader/[id]`로 이동한다. 현재 페이지 하나를 로컬 파일 URI로 읽고 `contain`으로 맞춘다. 양방향의 물리적 좌우 버튼, 페이지 번호, 첫·마지막 경계, 서재 이동, 준비 중 표시와 오류 복구를 제공한다. 방향을 변경하거나 회전해도 현재 페이지를 유지한다. 읽던 위치와 방향의 재실행 저장은 #10에서 구현한다.

페이지 파일이 없으면 열기 시 원본에서 다시 검증·추출한다. 디코딩 오류에서는 같은 이미지 재시도, 다른 페이지 이동, 원본 재추출이 가능하다. 원본에서 복구해도 현재 페이지 번호를 유지한다. 원본이 없으면 다시 가져오기 안내를 표시한다. 화면 이탈은 AbortSignal로 처리하며 원본 파일은 보존한다.

## Android 실행 결과

2026-10-12, Pixel 9 / Android 16 API 36 개발 빌드에서 실제 파일 선택기로 합성 샘플을 가져와 검증했다. ZIP 삽입 순서는 10, 2, 1이며 열람 순서는 빨강(1), 초록(2), 파랑(10)이다. 샘플은 240×360 PNG 세 장이며 개인 자료를 사용하지 않았다.

| 항목 | 관찰 결과 |
| --- | --- |
| 서재 → 만화 열기 | 로컬 첫 이미지와 1 / 3 표시 |
| 좌→우 이동 | 오른쪽 다음으로 2, 3 이동; 첫 이전·마지막 다음 비활성 |
| 우→좌 이동 | 같은 페이지 유지 후 왼쪽 다음·오른쪽 이전; 경계 비활성 정확 |
| 회전 | 우→좌 2 / 3 상태에서 가로 회전 후 초록 이미지·번호·방향 유지 |
| Android 시스템 뒤로 가기 | 서재로 복귀 |
| 캐시 누락 | 샘플의 2.png만 삭제 후 다시 열기; 원본에서 자동 재생성 |
| 이미지 오류 | 샘플의 10.png만 손상시킨 후 이동; 오류·재시도·복구 버튼 표시 |
| 같은 이미지 재시도 | 손상된 파일에서 오류를 유지하고 복구 가능 |
| 원본에서 복구 | 10.png를 정상 1035바이트로 재생성, 파랑 이미지·3 / 3 유지 |

회전 검증 후 에뮬레이터 자동 회전 설정을 복원했다. 이 기록은 합성 소형 이미지에 대한 결과이며 고해상도 메모리와 긴 책의 성능 검증은 #7에서 수행한다.

## 자동 검증 및 남은 범위

타입 검사, Expo 린트, 23개 Node 테스트(주소 파싱·양방향 경계 포함), iOS와 Android의 JS 번들 생성이 통과했다. React 훅의 정리, 비동기 결과의 화면 이탈 방어, 접근성 버튼 역할과 비활성 상태, 현재 페이지 하나만 마운트하는 구조를 점검했다.

iOS 네이티브 실행은 Xcode 라이선스 미동의로 `xcrun simctl`이 실패하여 아직 검증하지 못했다. 번들 생성으로 이를 대신하지 않는다. #6은 iOS 실행 확인 전까지 진행 중으로 유지한다. 확대·스와이프는 #9, 세로 스크롤은 #8, 위치 저장은 #10의 범위이다.
