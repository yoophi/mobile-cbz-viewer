# 세로 스크롤 열람 (#8, 진행 중)

페이지 모드와 세로 스크롤은 같은 자연 정렬 페이지 목록과 `{index, fraction}` 위치 모델을 사용한다. 세로 스크롤의 fraction은 페이지 이미지 상단에서 현재 화면 상단까지의 비율이다. 모드 전환은 현재 페이지를 보존하며, 화면 폭·높이가 바뀌면 새 목록의 같은 이미지 위치로 이동한다. 읽던 위치·모드의 재실행 복원은 [#10 구현 기록](reading-state.md)에 남긴다.

## 이미지 크기와 고정 레이아웃

SQLite schema 4는 페이지의 width·height를 추가한다. schema 3의 보관 파일·ready 상태·표지·순서를 유지하고, 기존 추출 파일의 크기는 해당 책을 열 때 헤더에서 읽어 보충한다. PNG IHDR, JPEG SOF/EXIF 회전, WebP VP8X/VP8/VP8L을 작은 읽기와 파일 seek로 확인한다. 전체 이미지 디코딩으로 책의 모든 페이지 크기를 구하지 않는다. 손상되거나 크기를 읽지 못한 페이지에는 고정 비율의 오류 자리와 원본 복구 버튼을 제공한다.

FlatList의 구간 높이·offset을 이미지 로드 전에 계산하고 getItemLayout에 제공한다. 이미지가 늦게 로드되어도 목록 높이가 변하지 않는다. 화면에 보이는 구간과 앞뒤 한 구간만 이미지 참조를 보유한다. 네이티브 좌표의 작은 반올림 차이가 페이지 시작점을 이전 페이지의 간격으로 오인하지 않도록 경계를 보정한다. 마지막 짧은 페이지에도 화면 상단으로 이동할 수 있는 footer 공간을 둔다.

## 디코딩과 캐시

다른 화면으로 이동하면 Expo Router의 focus 해제 시 페이지·구간 이미지를 제거하고 작업·캐시 보호 참조를 해제한다. 탐색 스택에 화면이 남아 있어도 이전 책의 이미지를 계속 유지하지 않는다. 돌아오면 같은 위치에서 책을 다시 연다.

화면 근처의 소스 페이지를 한 번에 하나씩 처리한다. 소스는 최대 너비 1,280px·높이 32,768px·16 MiPixels로 먼저 줄인 뒤 방향을 정규화한다. 원본 메타데이터가 128 MiPixels를 넘으면 스크롤 오류를 표시한다. 줄인 소스를 약 1,024px 높이의 PNG 구간으로 저장하며, 마지막 구간은 남은 픽셀만 포함한다. 예를 들어 512×30,000 이미지는 30개 구간이다. PNG는 투명도를 보존한다. 표시할 때는 원본 비율을 화면 폭에 맞춘다.

같은 소스의 여러 표시 구간은 생성 작업을 공유한다. 마지막 참조가 해제되면 대기 작업을 취소하고, 진행 중인 네이티브 작업은 종료를 기다린 뒤 임시 파일을 정리한다. 성공한 페이지 캐시만 원자적으로 이동한다. 누락된 구간은 소스에서 전체 페이지 구간을 재생성한다. 소스·원본 CBZ는 지우지 않는다.

구간 캐시는 전체 추출 캐시 512 MiB 안에서 최대 128 MiB를 사용한다. 화면 근처 소스는 보호하고 나머지 구간 캐시는 최근 사용 시각 순으로 정리한다. 저장 전에 최악 PNG 크기를 예약하고 실제 생성 크기를 재확인한다. 활성 책이라도 화면에서 벗어난 페이지 구간 캐시는 정리할 수 있다. 임시 생성 디렉터리는 다음 앱 시작 때 정리하며, 네이티브 이미지 로더의 디스크·메모리 캐시도 생성 종료 후 비운다.

소스 처리 중에는 16 MiPixels 비트맵만으로 약 64 MiB를 쓸 수 있다. 이는 화면 구간 비트맵과 별도인 일시 사용량이며, iOS 방향 정규화의 추가 복사 여부와 저메모리 실기기의 피크는 아직 검증하지 않았다. 구간 65,536개 또는 논리 높이 16,000,000을 넘는 회차는 페이지 모드 사용을 안내한다.

## 검증

- Node 테스트 35개: 헤더·회전·깨진 메타데이터, 구간의 빈틈 없는 범위, 이미지 비율·위치 왕복·화면 폭 변화·좌표 반올림 포함.
- Android API 36 네이티브 검사 8개: schema 3→4 보존, PNG/JPEG/WebP 크기와 네이티브 정규화 일치, DB 재열기, PNG 구간 실제 로딩, 512×30,000의 전체 높이, 작업 공유·취소·누락 캐시 재생성.
- 40페이지 합성 책 UI 검사: 스크롤 이동, 모드 전환, 가로·세로 회전, 마지막 긴 페이지의 구간 이동. 첫 화면에서 2개 소스만 준비되고 마지막 검사 후에도 7개 소스만 생성되었다. [원시 결과](validation/android-scroll-reader.json).
- 화면 focus 해제 수정 후 반복 UI 검사: 기존 구간 캐시 7개를 재사용했고 마지막 이미지의 표시 구간이 실제로 바뀌는 것을 검사했다. [반복 결과](validation/android-scroll-final-reader.json).
- 1,000페이지 책: 스크롤·모드 전환·양방향 회전을 확인했고 기존 구간 캐시 5개를 재사용했다. 챕터 전체 이미지의 구간 캐시는 생성하지 않았다. [결과](validation/android-many-page-scroll-reader.json).
- 변경 후 추출·중단 복구 17개, 페이지/표지 6개, 캐시 정책 4개의 Android 네이티브 회귀 검사도 통과했다. [전체 결과](validation/android-scroll-regressions.json).

40페이지 UI 검사에서 정지 상태 PSS는 약 382–425 MiB, Bitmap malloc은 약 14.7–25.7 MiB였다. 소스 생성 중의 순간 피크나 릴리스·실기기 한계를 증명하는 수치는 아니다. 기준 기기는 앞선 메모리 기록과 같은 Pixel 9 API 36 AVD이다.

화면 focus 해제 수정 후 반복 검사는 PSS 약 389–420 MiB, Bitmap malloc 약 16.7–25.1 MiB였다. 같은 프로세스에서 연 1,000페이지 책은 PSS 약 404–408 MiB, Bitmap malloc 약 19.3–25.1 MiB였다. 초기 검사와 반복 검사는 캐시 준비 상태가 다르므로 처리 중 피크의 직접 비교로 해석하지 않는다.

재현하려면 개발 앱에서 `scripts/generate-reader-stress.py`의 합성 CBZ를 먼저 가져오고 해당 서재 id로 실행한다. 개인 만화 파일·계정 이름은 결과에 기록하지 않는다.

```sh
python3 scripts/verify-android-scroll.py --book-id 2 --last-page
python3 scripts/verify-android-scroll.py --book-id 4
```

개발 전용 `mobilecbzviewer://dimensions-diagnostics`는 별도 DB·원본·추출·임시 디렉터리만 사용한다. 검사 결과는 앱 문서 디렉터리의 dimensions-probe-result.json에 기록한다.

## 남은 완료 조건

추가 Android 검증 6개에서 128 MiB 캐시 예약에 따른 오래된 비활성 구간 정리·활성 구간 보호, 활성 구간만으로 용량이 찬 경우 오류와 한도 유지, 참조 해제 후 재생성, 실제 PNG 구간 출력 뒤 취소·임시 파일 정리·재시도, 재열기 시 중단된 임시 디렉터리 정리를 확인했다. [원시 결과](validation/android-scroll-cache-pressure.json). 용량 압박은 별도 진단 디렉터리에 1 MiB 단위로 실제 파일을 써 재현했다. 개인 서재에는 검사 데이터를 만들지 않는다. 개발 전용 경로는 `mobilecbzviewer://scroll-cache-diagnostics`다.

#8은 iOS 실행 검증과 장시간/저메모리/실기기 캐시 압박 검증이 남아 진행 중이다. Xcode 라이선스 승인 전에는 iOS 네이티브 실행을 검증할 수 없다. iOS 번들 성공으로 이를 대신하지 않는다. PNG/WebP의 EXIF 회전, 애니메이션 이미지, 생성 중 프로세스 종료와 네이티브 임시 출력 잔여 파일도 추가 확인이 필요하다. #7의 플랫폼별 메모리·캐시 검증도 함께 유지한다.

API 근거: [Expo SDK 57 Image](https://docs.expo.dev/versions/v57.0.0/sdk/image/), [ImageManipulator](https://docs.expo.dev/versions/v57.0.0/sdk/imagemanipulator/), [React Native 0.86 FlatList](https://reactnative.dev/docs/0.86/flatlist).
