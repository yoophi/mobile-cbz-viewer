# 서재 파일 관리

schema 6은 원본 내용 식별자를 저장한다. 파일 이름이 같아도 내용이 다르면 별도 책으로 보관하며, 이름이 달라도 같은 파일은 중복으로 안내한다. 기존 서재의 식별자는 같은 크기의 파일을 가져올 때 필요한 후보에만 계산한다. 마이그레이션 때 모든 원본을 읽지 않는다.

Expo FileSystem의 네이티브 MD5는64 KiB씩 읽는다. 후보를 찾은 뒤 두 파일을64 KiB씩 직접 비교하고 블록 사이에 JS 실행을 양보한다. 해시가 같은 것만으로 기존 파일을 중복 처리하지 않으며, 전체 파일을 JS byte 배열이나 Base64로 만들지 않는다. 이는 파일 동일성 확인이며 보안 서명은 아니다. 압축 안전성·CRC 검증은 이후 추출 단계에서 계속 수행한다. 같은 이미지를 다른 ZIP 메타데이터로 다시 압축한 파일은 다른 파일로 보관한다.

선택 파일 복사 전에 원본 크기와32 MiB 여유 공간을 확인하고, 복사 후 크기·식별자를 확인한다. 실패 시 미등록 복사본과 앱 캐시의 선택 파일을 정리하며 재시도가 가능하다. 파일 선택기의 원본은 삭제하지 않는다. 네이티브 MD5 호출은 동기식이므로 대용량에서 UI 대기 시간과 메모리 측정은 별도 검증해야 한다.

## 삭제와 복구

서재의 삭제 버튼은 확인 대화상자를 거친다. DB에 `deleting` 상태를 먼저 기록하고 원본·추출/스크롤 캐시·표지·임시 구간을 삭제한다. 마지막 DB 삭제는 외래 키를 통해 페이지·읽던 위치·캐시 접근 기록을 함께 정리한다. 실패하면 삭제 의도와 오류를 남겨 다시 시도할 수 있고, 다음 실행에서도 삭제를 이어간다. 삭제 대기 항목의 추출은 상태를 덮어쓰지 않는다. 실제 열람/파일 처리가 끝나기 전에는 삭제를 거부한다.

파일 경로는 해당 서재가 생성한 상대 경로만 정리한다. 예전 버전의 외부 URI나 다른 책의 폴더는 삭제하지 않는다. 삭제된 책의 대기 저장·오류도 정리하고, 뒤늦은 읽기 상태 저장이 항목을 다시 만들지 않도록 한다.

원본이 없는 책에는 `원본 다시 가져오기`를 표시한다. 사용자가 선택한 기존 항목만 복원하며 ID·등록 시각·읽던 위치를 유지한다. 식별자가 있는 항목에 다른 원본을 선택하면 거부한다. 식별자가 없는 예전 항목은 선택 파일로 복원하므로 원래 책을 선택해야 한다. 이후 페이지 수가 달라지면 기존 읽기 상태 정규화 규칙으로 위치를 보정한다.

서재는 페이지·읽기 모드를 표시한다. 서재 복귀 시 진행 중인 위치 저장을 기다리고, 파일 선택기에서 돌아오는 focus 갱신이 가져오기 작업 잠금을 풀지 않도록 한다.

## Android 검증

- 격리된 파일 관리 검사18개: v5→v6 보존, 이름 변경 중복, 동명 다른 파일, 강제로 같은 후보 해시를 준 바이트 차이, 열람 보호, 삭제와 다른 책 보존, 실제 DB 삭제 실패·재시도, 중단된 삭제 재개, 원본 누락·다른 파일 거부·동일 항목 복원, 네이티브 저장 대상 생성 실패·재시도.
- 기존 네이티브 회귀35개: 읽기 상태8·캐시4·페이지6·ZIP 안전성/복구17.
- 제품 UI7개: 시스템 파일 선택기 가져오기, 서재의 읽던 위치, 중복 안내, 삭제 취소, 확인 후 정리, 다른 책 보존, 선택기의 원본 유지.
- 타입 검사·린트·44개 Node 테스트와 iOS/Android JS 번들 생성.

[네이티브 결과](validation/android-file-management-regression.json), [UI 결과](validation/android-file-management-ui.json)에 범위를 기록한다. 격리 검증은 개발 앱에서 `mobilecbzviewer://file-management-diagnostics`를 연다. 제품 UI 검증은 현재 소스를 로드한 Android 개발 APK에서 `python3 scripts/verify-android-file-management.py`로 실행한다. 직접 만든 작은 테스트 CBZ만 사용하며 기존 책이 같은 테스트 이름으로 존재하면 중단한다. 결과 비교용 SQLite 파일은 읽기 전용 복사본이다.

## 남은 검증

iOS 네이티브 실행, 실제 저장 공간 부족, 대용량 내용 식별·중복 비교의 대기 시간과 메모리, 실제 프로세스 종료 중 삭제 복구는 아직 검증하지 않았다. 현재 중단 복구 검사는 격리 DB에 저장된 삭제 의도를 만들어 재열기로 확인한다. JS 번들 생성과 격리 검사를 실제 기기 검증으로 대신하지 않는다. 기존 이미지 메모리 초과 문제도 별도 미해결 상태다.
